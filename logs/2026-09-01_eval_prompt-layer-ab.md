## 過程中修正的一件事：語義保底門檻壓到 0.15

`prompt` 階段的語義保底檢查在這一輪**誤殺了 `p2_016`**（重疊 20%）。
看完整產出後確認是誤殺——

```
場景：a person gesturing towards a large group of diverse objects
產出：A figure stands amidst an overwhelming collection of diverse objects,
      their hand outstretched as if presenting or pointing toward the vast array
```

`gesturing` 被寫成 `hand outstretched as if presenting`，**語義完整保留**，
只是幾乎每個實詞都換了同義詞。加上 Task 8.3 已記錄的另一次誤殺（44%），
**觀察到的 16 次真實改寫裡這個檢查貢獻 2 次誤殺、0 次真陽性**。

原因是結構性的：**詞袋重疊率分不出「同義改寫」與「換題材」**，
而同義替換正是散文改寫在做的事。門檻從 0.5 調到 0.3 只是治症狀。

因此壓到 **0.15**，定位改為**災難偵測器而非品質閘**——只擋「重疊近乎為零」
（模型完全無視場景自己想圖）的情形，其餘交給人工抽驗。
誤殺會讓好產出變成 `failed` 列、要使用者手動重跑，代價比漏放高。
兩次誤殺都寫成回歸測試（`tests/stages/test_prompt.py`）。

## 結論

**閘門通過，Task 8.6 可以鋪開。**

- 語義符合度與構圖 **9 勝 1 敗 3 和**，四張硬卡裡 A 組拿下三張（`p3_037`、`p3_098` 略勝、`p1_046` 和），僅 `p3_084` 輸。
- 假文字**兩組完全相同**（2/13），自然語言語法既沒有改善也沒有惡化這一項。
- 觸發詞 13/13，內聚設計（觸發詞寫在 prompt 檔而非系統參數）在實測上站得住。

**沒有觸發中止條件**：自然語言組沒有明顯較差，觸發詞沒有漏字。

## 這一輪**沒有**證明的事

- **不能說自然語言「解決」了多元素構圖或假文字。** 假文字兩組打平，
  兩張出字的卡都追到語義層。CLAUDE.md 的已知限制照舊成立。
- **13 張的樣本判不出小差距。** 九項「略勝」是主觀目視，不是量化指標；
  真正確定的是四張「明顯勝」與一張「明顯敗」。
- **沒有比較 Phase 7 的實際成品圖。** 對照組用的是新的 `image_scene`，
  不是 Phase 7 當時那批（那批的場景是舊 extract 產的、品質較差）。
  這是刻意的——要隔離的是語法層，不是把語義層的改善混進來。
